# Zuzify-owned authentication emails

The signed Neon Auth send.otp and send.magic_link webhooks are handled by /api/auth-mail on Zuzify's Vercel deployment. Zuzify calls Resend using the existing server-only RESEND_API_KEY and sends from auth@zuzify.xyz. Neon continues generating, storing, expiring and verifying credentials and managing sessions. The endpoint does not store another copy of the code, expose it in responses or logs, or modify the managed neon_auth schema.

Deploy the endpoint and verify its GET health response, then configure the existing Neon Auth branch webhook at https://www.zuzify.xyz/api/auth-mail (the apex redirects). Subscribe only to send.otp and send.magic_link, timeout 8 seconds. This replaces the default mail delivery for those events. Preserve other subscriptions if added later. Test with a consenting account, verify the actual inbox and successful code redemption; roll back webhook configuration if delivery fails. Keep email verification requirements unchanged during the migration. Disable click tracking for authentication emails in Resend. Never commit or log keys or codes. Resend event idempotency prevents duplicate accepted sends on webhook retries.
