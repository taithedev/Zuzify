# Social space
Apply apps/xyz/db/social.sql to the central accounts database. Only verified, non-banned users can access this feature. Friends exchange a rotating high-entropy private invite code and must accept the request before text chat. Profiles are private to accepted friends. Blocking stops new messages; removing a friend disables chat. Text is rendered as text, not HTML. There are no public user searches, open DMs, attachments, voice or calls. Reports copy only the specific reported message into a separate queue; owners cannot browse arbitrary chats in the UI. The database is not end-to-end encrypted. Messages are stored in Neon and the latest 80 are displayed; implement a retention and deletion policy before broad public launch.
Preset avatars and banners are shared with accepted friends immediately. Custom images are re-encoded as metadata-free static WebP and stored as private previews pending review. Public or friend-visible custom uploads must remain disabled until appropriate moderation is in place; the fields avatar_image/banner_image are reserved for approved images. Do not auto-approve uploads. No external image URL embedding.
Basic request/message limits are provided; production abuse controls, age-appropriate moderation, retention and end-to-end two-account tests remain necessary. The interface polls messages every five seconds while the tab is visible.
